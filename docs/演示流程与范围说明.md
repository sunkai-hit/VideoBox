# VideoBox 交互原型演示流程与范围说明

## 一、模型生产平台

数据集与标注管理 → YOLO/ReID训练 → PT→ONNX→RKNN转换与INT8量化 → PC端仿真验证 → 制品版本发布。

自然语言建模助手使用规则驱动的演示逻辑；场景描述解析、配置建议和自动生成模拟任务均不是实际大模型调用。在线标注是可点击的目标框标注与复核示意，未实现真实图像标注引擎。

## 二、中心管理平台

统一接收已发布模型包，管理制品版本；集中查看设备注册、心跳、硬件负载；配置视频通道、ROI、置信度、IOU、告警防抖及轮询调度；下发至边缘盒子；接收告警、抓拍并完成确认标记、导出；演示多账号与权限列表及审计日志。

## 三、边缘算法盒子

展示 IPC / GB28181 流状态、H.264/H.265 硬解码方向、RKNN模型加载、ByteTrack目标跟踪示意、业务规则告警、本地缓存与断网恢复补报；本地日志、心跳和远程运维指令模拟。

## 四、演示边界

- 不连接真实摄像头、GB28181平台、RK3588设备或NPU驱动。
- 不运行真实YOLO / ReID训练、ONNX导出、RKNN量化和ByteTrack。
- 模拟视频与检测框仅用于表现界面与交互层次。
- 浏览器本地数据不会同步到其他设备或真实服务端。
- 原型不是已交付的业务系统，也不能作为真实性能验收依据。

## 五、优先需求确认问题

1. 首期是否完整交付三个系统；AI智能体与现场数据回流是否延后。
2. 模型制品上传与中心仓库的权限、版本与回滚规则。
3. 多算法同通道并发或轮询策略、边缘资源分配。
4. ROI、置信度、IOU和防抖等配置在中心与边缘的生效时点。
5. 离线缓存容量、重试、消息去重、补报顺序和证据存储。
6. 本地盒子是否需要操作页面，还是仅提供中心运维能力。
